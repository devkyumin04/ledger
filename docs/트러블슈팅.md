# 트러블슈팅 기록

겪은 문제와 해결. 같은 문제를 두 번 겪지 않기 위한 기록.

---

## 1. `-parameters` 컴파일 옵션 — `@PathVariable`, `#{}` 바인딩 실패

**증상** — Spring 7.0 / MyBatis 조합에서 매개변수 이름이 사라져 `@PathVariable`과 MyBatis `#{}` 바인딩이 실패.

**원인** — 자바는 컴파일 시 파라미터 이름을 버려 바이트코드에 `arg0`, `arg1`만 남음. Spring 6.1+부터 `-parameters` 없이는 이름 추론을 하지 않음.

**해결** — `-parameters` 옵션을 **`build.gradle`과 STS Preferences 양쪽** 다 켜야 해결. 한쪽만 켜면 로컬은 되는데 CI에서 터지거나 그 반대.

**교훈** — MyBatis 매퍼 파라미터가 2개 이상이면 `@Param`을 붙여 컴파일 옵션 의존을 없애는 게 안전.

---

## 2. Spring Boot welcome page가 Security와 충돌

**증상** — static `index.html`을 welcome page로 두고 `permitAll("/")`을 넣어도 401.

**해결** — `@GetMapping("/")` 컨트롤러(`RootController`)로 우회. `/views/main.html`로 리다이렉트.

---

## 3. 에러 페이지에서 CSS 404

**증상** — 404/500 에러 페이지의 CSS가 안 먹음.

**원인** — 에러 페이지는 forward라 URL이 원래 요청 주소에 머무름. CSS를 상대경로로 걸면 그 주소 기준으로 찾아서 404.

**해결** — 절대경로 필수.

---

## 4. `authGuard`의 상대경로가 폴더 깊이에 따라 깨짐

**증상** — `'user/login.html'` 같은 상대경로가 `/views/personal/` 깊이의 페이지에서 깨짐.

**해결** — 절대경로로 수정. 이후 프로젝트 전체 원칙으로 확정 (ADR-033).

---

## 5. 미분류 자동생성 시 순환참조

**증상** — `UserService`가 `PersonalCategoryService`를 주입받으면 순환참조 위험.

**해결** — `UserService.signup()`에서 `PersonalCategoryMapper`를 직접 주입. `@Transactional`로 묶고 롤백 테스트까지 확인.

**교훈** — Service가 다른 도메인의 데이터를 건드릴 땐 그 도메인의 Service가 아니라 Mapper를 직접 주입하는 패턴. 카테고리 삭제 시 거래 이관에도 동일하게 적용 (ADR-023).

---

## 6. macOS 사이드카 — 디스플레이가 데스크탑 1로 합쳐짐 (개발 환경)

**증상** — 재부팅 후 맥북·아이패드가 각각 데스크탑 1·2였던 게 하나로 합쳐지고 세 손가락 스와이프가 안 됨.

**원인** — 시스템 설정 → 데스크탑 및 Dock → Mission Control → "각각의 Spaces가 있는 디스플레이"가 꺼짐.

**해결** — 토글을 켜고 **재부팅** (로그아웃만으론 앱이 취소시킬 수 있음). 터미널 강제 적용:
```
defaults write com.apple.spaces spans-displays -bool false && killall SystemUIServer
```
사이드카 목록에 iPad가 안 뜨면 USB-C 케이블로 직접 연결하면 즉시 뜸.

## 7. 캐치올 예외 핸들러가 스프링의 4xx 를 500 으로 덮어씀

**증상** — 필수 쿼리파라미터(`?year=`, `?version=`)를 빼고 호출하면 400 이 아니라 **500 "서버 오류가 발생했습니다"** 가 나감.

**원인** — 스프링이 던지는 `MissingServletRequestParameterException` 에 대응하는 핸들러가 없어서,
`GlobalExceptionHandler` 맨 아래의 `@ExceptionHandler(Exception.class)` 캐치올이 삼켜버림.
클라이언트 실수인데 서버 잘못이라고 응답하는 꼴.

**해결** — 전용 핸들러 추가. 어떤 파라미터가 빠졌는지도 함께 응답.
```java
@ExceptionHandler(MissingServletRequestParameterException.class) → 400
```

**교훈** — 캐치올 핸들러가 있으면 스프링이 원래 4xx 로 처리해줬을 MVC 예외까지 전부 500 이 된다.
새 API 를 만들 때마다 "이 요청이 잘못되면 어떤 예외가 나는가"를 한 번씩 확인할 것.
(`MethodArgumentTypeMismatchException` 은 이미 등록되어 있었지만 이건 빠져 있었다)

## 8. QA 스크립트 — 중첩 명령치환에서 curl body 유실 (macOS /bin/sh)

**증상** — 같은 요청인데 어떤 케이스는 201, 어떤 케이스는 400 "요청 형식이 올바르지 않습니다".

**원인** — macOS `/bin/sh`(bash 3.2 POSIX 모드)에서 아래처럼 중첩하면 본문이 유실됨.
```bash
check 3 201 "$(req POST /path "{\"a\":1}")"   # ✗ body 가 사라짐
```
변수에 먼저 담은 케이스만 통과해서 원인을 찾는 데 두 번 헛발질했다.

**해결** — 중첩을 없앰. 본문은 항상 `B=...` 변수에 담고, 요청+판정을 한 번에 하는 `t()` 헬퍼 사용.

**교훈** — 기대 상태코드와 실제 실패 코드가 같으면(둘 다 400) **가짜 통과**가 난다.
상태코드만 보지 말고 응답 body 도 검사할 것. (`docs/qa-체크리스트.md` 참고)

## 9. 정리 스크립트가 자기참조 FK 에 막힘 — 2계층 카테고리를 처음 만든 뒤

**증상** — 여태 잘 돌던 `qa/reset-data.sql` 이 갑자기 실패.
```
ERROR 1451: Cannot delete or update a parent row: a foreign key constraint fails
(`ledger_db`.`personal_categories`, CONSTRAINT `FK_PCAT_PARENT` ...)
```

**원인** — `DELETE FROM personal_categories WHERE is_default_yn = 'N'` 한 문장으로
부모와 자식을 같이 지우려 했다. MySQL 은 한 DELETE 안에서 행 삭제 순서를 보장하지 않으므로,
부모가 먼저 지워지는 순간 자식이 아직 그 부모를 참조해 FK 위반.

그전까지 안 걸린 이유는 **QA 스크립트가 2계층 카테고리를 만든 적이 없었기 때문**이다.
`category-transfer.sh` 의 케이스 11(자식 있는 대분류 삭제 → 400)이 처음으로
부모-자식 쌍을 실제로 만들면서 드러났다.

**해결** — 소분류 → 대분류 순서로 두 문장으로 나눔. 2계층 제한(ADR-019)이라 두 번이면 충분.
```sql
DELETE FROM personal_categories WHERE is_default_yn = 'N' AND parent_category_num IS NOT NULL;
DELETE FROM personal_categories WHERE is_default_yn = 'N';
```
`reset-all.sql` 은 `SET FOREIGN_KEY_CHECKS = 0` 으로 감싸 이 문제가 없다.
부분 삭제 스크립트에서 FK 체크를 끄지 않은 이유는, 껐다가 '미분류' 를 잘못 지워도
DB 가 막아주지 못하기 때문. 전체 삭제와 부분 삭제는 안전 장치를 다르게 둔다.

**교훈** — QA 케이스가 늘면 **테스트 데이터의 모양**도 늘어난다.
문서에만 있던 제약(2계층)을 처음 실제로 만들어보는 순간, 그 제약을 고려하지 않은
주변 스크립트가 깨진다. 기능 QA 를 추가하면 정리 스크립트도 한 번 돌려볼 것.
