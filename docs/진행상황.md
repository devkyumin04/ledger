### 6단계 이관 QA 결과 (35/35, 2026-09-13)

`qa/test-category-transfer.sh` — 상태코드가 아니라 **부수효과**(거래가 옮겨졌는가)를 검사.
삭제 후 목록을 재조회해 `categoryNum`·`categoryName`·`version`을 확인한다.

- 경계값 — 거래 0건(이관 0행도 정상) / 1건 / 3건 전부 이동
- 타입 — 지출→지출 미분류, 수입→수입 미분류. E·I 공존 시 반대 타입 거래 불변
- 순서 의존 — 이관이 올린 `version` 때문에 옛 version 수정은 409, 새 version은 200.
  이미 삭제된(`use_yn='N'`) 거래는 이관 대상 아님 (DB 직접 확인)
- 부수효과 — 남의 카테고리 403 / 자식 있는 대분류 400 일 때 **이관도 일어나지 않음**
  (검증이 이관보다 앞에 있다는 증명). 미분류 자체 삭제 403 — 이관 목적지 보호
- `defaultCategory` null 체크는 넣지 않음 — 미분류는 `signup()`이 항상 생성(ADR-020)하고,
  깨지는 경로는 SQL 로 유저를 직접 INSERT 한 경우뿐. NPE 가 나도 `@Transactional` 이 롤백

카카오맵 장소 입력은 Sprint 5. 지금은 위치 없이.
